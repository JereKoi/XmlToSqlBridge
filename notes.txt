Namespaces, XNamespace, their meaning and management in SOAP-architecture
	- I learned one of most critical SOAP-world's rule. Why namespaces exist?
	  In integrations and web services, XML-documents can combine different elements
	  from different systems. Name spaces such as xmlns="[http://tempuri.org/]
	  (http://tempuri.org/)" ensure that element name Product, is not mixed with some
	  other system's similarly named element.
	  
	- I learned that C# does not find elements purely based on strings like "Product"
	  if document has only namespace defined. 
	  By creating XNamespace ns ="[http://tempuri.org/](http://tempuri.org/)"; and
	  combining it to element name (ns + "Product"), I tell program exactly in which
	  system that product is searched in.

Defensive programming and null-safety

Primary Key:
	- Primary key is unique and it makes sure that each row is always unique. Not any other
	  row can share same primary key (perusavain). For example two products cannot have same ID-
	  number. Primary key field cannot be never null. Each row has to be active identifier.
	  Primary key upholds data integrity. Primary key works as last defence. If program or 
	  integration tries to accidentally save existing info again, database stops it
	  automatically, such as Violation of primary key-error. Primary key also improves
	  speed of queries. Database creates automatic indexing around primary key, which 
	  makes searching for data, updating and deleting with specific ID very fast especially when
	  table has millions of rows.

Why duplicate rows are issue?
	- Data goes wrong, wrong raports and calculations. If database has two copies of same product,
	  all statistics and calculations goes wrong. For example warehourse price as whole or product
	  amount shows way too high number.

Business fail and catasthrophies, operational errors:
	- In integrations and webshops, duplicates can in worst scenarion cause situation where
	  customer gets two products, customer is billed twice or system thinks, that there are
	  more than one order. Some tables which have two rows, but data has been updated
	  such as price has been updated, database does not know which row is the right one
	  (single source of truth). Duplicate rows also cause unnecessary resource consumption.
	  Even though hard disks are cheap and in million class system unnecessary duplicate rows
	  cause turbulance in database, which causes queries to be slower and make friction on
	  server's memory. This is why databases have always strict rules, like those PRIMARY KEY,
	  which works as automatic bouncer and stops faulty data to get into party.

Error handling and logging:
	- Try catch block is useful to catch exceptions and errors. Catch block is used to prevent
	  program to not crash if something goes wrong. Logging is used to write what went wrong and when.

Upsert and Merge:
	- Smart data management. Instead of system only adding rows blindly or crash to duplicates,
	  MERGE-clause can check situation on fly and decide itself if it needs to use INSERT or
	  if there is existing row and use UPDATE instead. Solely skipping duplicates would leave
	  old info to live on database. Upsert-model ensures, that for example product price changes
	  on SOAP API, also database price changes automatically to correct one. Integration reapplicability.
	  When database and SQL-clause sort duplicate issue and updates smartly, same integration job can
	  be ran again and again safely without errors or data corruption.

Transactions and rollback:
	- Lets think of situation where SOAP-API sends me at once 100 products and my program starts
	  to save them from list one by one to database. Products 1-49 saving is succesfull. On
	  product 50 is some unexpected error, for example required data is missing or database connectino
	  cuts of momentarily. Without transaction, producst 1-49 would be on database, but rest of 50
	  products end up missing from database. Database is now halfway (half-baked), data is inconsistent.
	  Transaction being all or nothing, either all 100 products are saved succesfully (commit) or
	  even one faulty saving results into error, database rolls back all and not even one
	  data is changed on database. Database remains intact.

How to use transcations in code?
	- In Microsoft.Data.SqlClient-library transaction is started straight away from opening the connection
	  (connection.BeginTransaction()) and it is tied to commands. BeginTransaction is the batch (job).

I deleted necessary info from mock SOAP response, but transcation did not rollback. Why?
	- I did negative test, so deleting necessary info from SOAP-response to see if rollback works.
	  Reason why transaction did not go to error and catch-block didnt activate despite deleting Id
	  and Name from one of products on SOAP-response. Reason lies on these two lines;
	  if (int.TryParse(p.Element(ns + "Id")?.Value, out int id) &&
		int.TryParse(p.Element(ns + "Price")?.Value, out int price))
	  When I deleted Id from SOAP-response, p.Element(ns + "Id")?.Value returned null.
	  int.TryParse(null, out int id) returned false. In human communication it said: "Hey
	  this is not valid whole number"). Because if statement returned false, whole block's
	  code including database command was not performed at all. Program only skipped that
	  specific product unnoticed and went through rest of them in loop and performed
	  transaction.Commit(); to the end. Because faulty data was not even attempted to be
	  saved to database, no exception happened. This raises architectural question,
	  Is it right if SOAP-response is missing data, program only skips product and
	  continues. Maybe sometimes this is on purpose, but often dangerous as errors or missing
	  information was missing without anybody noticing it. Option B strict validation after fail.
	  With option B question is that do I want so that product is missing some critical data such
	  as Id, does program raise alert, throw new exception or rollback whole batch run? I will
	  go with option B, because in enterprise integrations it is used to build quality and 
	  trustworty processing.

What I learned after adding transaction triggering exceptions to code?
	- Adding strict validation (fail fast) to code, instead of my program silently skips
	  ahead when faulty SOAP-response has product that is missing id or whatnot, it immediatly
	  throws exception and catch-block is activated to rollback whole operation. Errors
	  are needed to be known immediatly, so that it is easy to react to them so that faulty
	  data does not spread to database. Atonomic and safety nets (All or nothing). Transaction
	  makes sure that database remains intact. Either all batch data has gone through succesfully
	  (Commit) or even if one product is faulty, all changes are rolledback. Database is never left
	  in half-baked state or messy state. Transactions makes sure that error processing is structured 
	  and safe. When code gets to exception, catch block reacts to this and acts as safety net for
	  database, making sure that data remains intact and leaves to humans log message to react to when
	  something goes wrong.

Commit:
	- Commit means tranasction ending. When program calls transaction.Commit(); it tells database:
	  "All batch products were handled succesfully without any errors. You can now save all changes
	  (additions and updates) entirely to database." Commit () = Accept and save all changes
	  (when everything went alright). Rollback() = Rollback everything (when something went wrong,
	  so that database is not left in half-baked state/some data saved, some data missing).

What is Serilog:
	- Serilog is popular and extremely efficient logging library in .NET world (C#, F# etc).
	  It's main idea and biggest advantage is structured logging. Traditional way of logging
	  would be pure strings: Console.WriteLine($"User {userId} made a mistake with product {productId}).
	  Computer and log programs only see this as one long text. With Serilog, Data is saved in
	  structured format with for example JSON in background. Then user Id and product Id is their own
	  seperate fields. You can later easily search and filter log system; show all errors where productId
	  was 101. Is it generally used? Yes and it is extremely popular. Serilog is basically a standard
	  way of logging, de facto standard part of .NET ecosystem. Together with Microsoft's inbuilt 
	  log system, Serilog is one of the most downloaded and used libraries in the world. It is used
	  daily everywhere from micro services to enterprise cloudsystems. 
	  
Why it is so popular:
	- Sinks. Serilog has ready made addons so called sinks for almost any use and purpose. You can
	  direct same logs with one command into console, file, database, to cloud service such as
	  Azure Application Insights, AWS CloudWatch, Datadog) or more sophisticated log services such as
	  Seq or Elasticsearch. Serilog is also popular due to its easy integrability to Microsoft systems.
	  It works seamlessly with .NET's own ILogger-API, which makes it easy to use with modern ASP.NET Core
	  softwares as well. Performance is as well secret for popularity, Serilog is designed to withold
	  strong stress without it slowing down the main product/software. With learning Serilog, I am learning
	  a skill, which is needed in almost every professional C#-project in future.

I noticed Serilog working on console, but it didn't write anything to file, why?
	- This is classic first fail when taking serilog to use first time. It could be that
	  console application closes so fast that Serilog did not have time to write logs that were on
	  the memory to hard disk. Another reason is that Serilog needs one important command at the end
	  of program so that Serilog empties memory and closes program safely: Log.CloseAndFlush();
	  This row needs to be the very last one at the end of Main method. Also log files are created to
	  bin folder.

What if I run program more than once on same day, would it overwrite log file:
	- Serilog is designed so that if I run program on same day, Serilog notices that on that specific
	  day log file that carries that day's name already. Serilog does not empty it or replace is, but
	  instead it opens it and writes new log rows straight under neath the old logs. Instantly when day
	  switches at midnight and I start program next time, Serilog creates automatically new file with
	  that day's name as filename. Old logs stay safely in their own files. This is how during the same
	  day driven tests and jobs get saved neatly to same file in time order and no file disappears.

What is async/await?
	- It means transitioning from syncronous database queries ExecuteNonQuery to asyncronous calls
	  ExecuteNonQueryAsync. Why this is important? In enterprise systems, database calls and SOAP-
	  web requests take time. async/await ensures that program does not stay long period of time waiting
	  for a response, but frees resources efficiently for handling other tasks.
	  Asyncronous can be thought as an restaurant. My old synchronous code is like going to restaurant
	  counter to order. After ordering, on counter, employee starts to prepare meal and I stay there
	  watching and do nothing until food is ready. Nobody else can order because I stay there and cashier
	  cannot do it's job. This is not ideal way and not efficient.
	  Asnycronous way (async/await): When I go order, I get on my hand an blinking alert and I say
	  at counter: "ring counter when food is ready". Meanwhile I sit down and drink water and do
	  other things. Alert rings and I go pick my food. SQL query calls and API calls such as SOAP
	  calls are all similar "waiting" situations. Database takes a little time to handle MERGE-clauses.
	  In synchronous code, program will stay waiting for answer. Asyncronous code frees computers
	  resources to do something else meanwhile.

How async looks like in code?
	- Asyncronous has three magic words:
	  async: Telling method that here are going to be used await.
	  Task: return type. Void changes into Task and Main method becomes async Task Main.
	  await: Commanc that says: "Wait that this database call is ready, but free up a thread to do
	  something else meanwhile".
	  In theory, database commands become Async like this:
	  connection.Open() -> await connection.OpenAsync()
	  insertCommand.ExecuteNonQuery() -> await insertCommand.ExecuteNonQueryAsync()

How async works?
	- When I add word async in from of method, I tell C#-converter two things. Allow await word usage.
	  Thanks to this word, method is allowed to use await commands. If async is missing, C# converter
	  will give error when I try to use await command. Second is that it allows to build state machine
	  underneath the hood. Converter changes my method behind curtains to smart structure, which
	  remembers where exactly in code it is going when we went to wait something. Note that
	  only async word does not make method running in background type thing. It only allows to wait.

How await works?
	- This is the magic word that makes all the work. When code meets this line where is await,
	  event is sent away. For example command is sent to database: "drive this MERGE clause and alert
	  when you are ready". This returns Task-object, in other words promise for incoming result.
	  Method is ended cleanly. Program does not get stuck on this row. Instead, method "stops" and
	  gives current process thread free back to .NET's thread pool so that it can do something else
	  meanwhile, like for example serve net page visitor or handle other information. When response
	  arrives from database, .NET wakes up method again, often with free processing thread and continues
	  running code exactly from where it left off so below await word.

What is Task?
	- Task means "event/quest" or promise of that something is going to happen in future.

What are I/O operators?
	- Asyncronous programming is most benefit from in I/O-operations (Network I/O, Database I/O,
	  File I/O), where program needs to wait for network or hard disk responses.

What is I/O?
	- It comes from words Input / Output. It means situation where computer's processors (CPU) and
	  fast central memory have to communicate to somewhere outside world or transfering data with
	  slow physical machines. Why I/O is different than regular code? Processor is incredibly fast.
	  It can do billions calculations in seconds. But instantly when it needs to find data over
	  internet or write to hard disk, things slow down million times. Processor needs to wait,
	  that slower components respond.

Examples of I/O operations in my own project:
	- I have built three I/O operations so far. Network I/O so network traffic meaning calling
	  SOAP-API. My computer sends over internet request to other server and waits unti there comes
	  an response. This takes time, milliseconds or seconds. Database I/O, database traffic. When
	  I send MERGE-clause to SQL server and wait for responses. Database reads or writes from 
	  it's hard disk data, which is for processor slow work. File I/O, disk operations. When
	  Serilog writes integration_log.txt file to database.

Why async/await would be fantastic here:
	- For these operations above async/await is fantastic. Because I know that database call or
	  SOAP-call takes time, I dont want to lock program's main thread to wait. Instead I free
	  it up for other tasks for time when I/O-operation is doing it's job in background.
